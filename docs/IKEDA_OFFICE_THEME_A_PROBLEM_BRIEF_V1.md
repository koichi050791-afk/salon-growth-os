# IKEDA OFFICE Theme A Problem Brief v1

更新: 2026-08-25

## Theme A

**経験をどう残せば、次に使えるのか。**

## 1. 最初に検証するProblem

美容師は経験年数が増えても、施術履歴は残っているのに、

- なぜその方法を選んだか
- なぜ別の方法を選ばなかったか
- どこで迷ったか
- 次回何を確認するか
- 前回の判断が実際にどうだったか

が残っていないため、似た相談が来ても毎回ほぼゼロから考え直している。

Theme Aでは、この問題を最初の検証対象とする。

商品を作る前に、まずこの問題が本人の言葉として繰り返し現れるかを確認する。

## 2. 想定読者

中心読者:

- 現場経験10〜25年程度
- 一定の顧客・売上はある
- 技術知識はある
- カルテや施術履歴は残している
- ただし判断理由や結果検証は体系的に残していない
- 毎回忙しく、長い記録は続かない
- 経験を後輩教育、発信、AI活用、商品化へ転用できていない
- 客数・長時間労働・SNS量産だけで成長したくない

## 3. 読者が使う可能性が高い入口言葉

上位概念から入らない。

避ける入口:
- 知的資産化
- Personal OS
- ナレッジマネジメント
- 意思決定システム
- Decision / Knowledge / Validation

優先する入口:
- カルテを書いても次に活かせない
- 前回どう考えたか思い出せない
- 同じような相談でも毎回考え直している
- 自分の得意をうまく説明できない
- 後輩に「感覚」としか言えない
- 何を記録したらいいか分からない
- 記録しても見返さない
- 経験年数は増えているのに、経験が積み上がっている感じがしない

## 4. 商品価値5層

### Feature

候補:
- 3分以内のケース記録
- 判断理由の記録
- あえてしなかったことの記録
- 次回確認ポイント
- 過去ケース比較
- AIによる整理・検索補助

Featureはまだ商品ではない。

### Surface Problem

- カルテはあるが、判断理由が残っていない
- 似た相談の過去ケースを探せない
- 次回来店時に前回の考えを再利用できない
- 記録項目が多すぎると続かない
- 経験が自分の頭の中だけにある

### Desired Outcome

- 次回来店時に前回の判断をすぐ使える
- 似た相談で過去経験と比較できる
- 判断が早くなる
- 自分の得意・判断基準を言語化できる
- 後輩や読者へ説明できる
- 現場経験から発信テーマを取り出せる

### Avoided Loss

- 同じ失敗を何度も繰り返す
- 毎回ゼロから考える時間を使う
- 20年以上の経験が本人の頭の中だけで消える
- 引退・退職と同時に経験が失われる
- SNSや商品を作るたびにゼロからネタを考える
- AIに渡せる一次情報がなく、一般論しか返ってこない

### Core Value

**働くほど、自分の専門性と知的資産が増えていく。**

現場経験を、その日の売上だけで終わらせず、次の施術・顧客体験・発信・教育・商品へ再利用できる状態を作る。

## 5. 現時点での最有力仮説

読者が最初に買いたいのは「美容師向けOS」ではない。

最初の有料需要候補は、より小さく具体的なものになる可能性が高い。

例:
- 何を記録すればいいか
- 3分で残すフォーマット
- カルテと判断記録の違い
- 記録したケースをどう見返すか
- 似たケースをどう比較するか

ただし、これは商品案であり需要証明ではない。
具体反応が出るまで制作しない。

## 6. 無料記事で確認すること

主資産:
- IP-004「美容師の経験を“勘”のまま終わらせない」
- IP-006 Manifesto
- IP-010「現場を言語化できる人」

無料記事で十分に渡す:
- なぜ経験が積み上がらないのか
- 実際に何を記録しているのかの概要
- 全件記録しない理由
- 判断理由・非選択・次回確認を残す意味
- 1件で一般化しない理由
- AIは最終判断をしないこと

無料で隠さない。

## 7. 需要シグナル

強いシグナル:
- 「具体的な記録項目を知りたい」
- 「フォーマットが欲しい」
- 「カルテとどう分けるの？」
- 「何件くらい残せば使える？」
- 「記録をどう見返す？」
- 「AIにどう入れる？」
- 「実際のケース例を見たい」
- 「自分でも同じ運用をしたい」

弱いシグナル:
- スキ
- PV
- 「参考になりました」
- 「面白いです」

弱いシグナルだけでGate 2へ進めない。

## 8. Problem Validationの記録単位

反応ごとに最低限残す。

- 日付
- どの記事 / 投稿から来たか
- 読者属性（分かる範囲）
- 読者の原文
- Surface Problem
- Desired Outcome
- Avoided Loss
- 何を欲しいと言ったか
- Theme A / B / C
- 強度: Weak / Medium / Strong

原文を最優先し、AIが読者の欲望を作らない。

## 9. Gate 0.5通過条件

Theme Aを有料検証へ進める最低条件:

- 独立した複数人から同種の具体質問が出る
- 「知りたい」ではなく、やり方・フォーマット・利用方法への要求がある
- Surface ProblemだけでなくDesired Outcomeが確認できる
- 既存無料記事で価値説明をしても、さらに実行方法を求められる

件数だけで自動判定しない。
同一人物の複数反応、友人の社交辞令、AI生成アンケートは独立Evidenceとして数えない。

## 10. 最初の無料テスト角度

新規記事を大量に作らず、既存IP-004を中心に入口を変えて反応を見る。

第一テストメッセージ:

**「カルテは残っている。でも、前回なぜそうしたかは残っていない。」**

第二テストメッセージ:

**「経験年数は増えているのに、似た相談で毎回ゼロから考えていないか。」**

第三テストメッセージ:

**「後輩に『感覚』としか説明できない経験は、まだ資産になっていない。」**

どれが最も具体反応を生むか観測する。

## 11. 今やらないこと

- 記録テンプレート完成版を作る
- Starter Kitを作る
- 有料noteを書く
- 講座化
- コミュニティ化
- SaaS化
- 汎用OSを売る

## 12. 次のHuman Action

池田が行うのは「商品制作」ではなく、実際の美容師の言葉を拾うこと。

特に、記事コメント、X / Threadsの返信、DM、知人美容師との会話などで出た具体的な言葉を原文のまま残す。

AIはその後に分類・比較・共通点抽出を行う。

## 結論

Theme Aの最初の検証Problemは、

**「施術履歴は残っているのに、判断理由と結果が残っていないため、経験が次の仕事へ再利用されない」**

とする。

売るのは記録ではない。

最終的に提供したい価値は、

**働くほど、自分の専門性と知的資産が増えていく状態**

である。
