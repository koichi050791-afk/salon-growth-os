# IKEDA OFFICE Second Engine / Industry note Strategy v1

更新: 2026-08-25

## 1. 最上位テーマ

**美容師の経験を、働く資産に変える。**

「美容師特化型OS」「AI×美容師」「美容師経営」「マーケティング」は独立テーマとして並列に扱わず、この上位テーマの下に統合する。

OSを作ること、AIを使うこと、noteを書くこと自体を目的にしない。

最上位目的は、現場美容師として20年以上積み重ねてきた経験・判断・失敗・検証を、その日の仕事だけで消費せず、次の施術・顧客体験・発信・商品へ再利用できる知的資産へ変えること。

長期的には以下の2軸を作る。

1. 130万円の技術売上を安定させる本業
2. 労働時間に比例しない第二収益エンジン

第二収益エンジンは完全な不労所得を意味しない。

**一度作った知的資産が、池田本人が施術していない時間にも繰り返し価値を生む状態**を目指す。

## 2. 第二エンジンの基本構造

```text
現場
↓
経験
↓
記録
↓
検証
↓
判断原理
↓
知的資産
↓
発信
↓
商品
↓
収益
```

現場美容師を辞めて別事業を作るのではない。
**現場そのものを第二エンジンのR&Dとする。**

## 3. 知的資産の製造ライン

```text
重要な現場ケース
↓
事実と仮説を分けて短時間記録
↓
なぜ選んだか / なぜ選ばなかったかを残す
↓
次回来店・類似ケースで確認
↓
一件だけで一般化しない
↓
共通点・相違点・反例・成立条件を確認
↓
他でも使える判断原理へ圧縮
↓
無料公開 / 有料資産 / 内部資産へ振り分け
↓
市場反応を見る
↓
更新
↓
商品候補へ
```

## 4. 記録対象

全件を記録しない。資産価値のあるケースだけを残す。

- 判断に迷った
- 複数の選択肢を比較した
- あえて何かをしなかった
- 前回判断の結果が確認できた
- 予想と違った
- 似た相談で別の判断をした
- 他の美容師にも使えそうな判断基準が見えた

## 5. AIの役割

AIへ任せる:
- 探索
- 整理
- 比較
- 過去ケース検索
- 共通点・相違点抽出
- 反例探索
- 次回確認候補
- 発信候補
- 既存記事更新候補
- 商品候補
- 監査

AIへ任せない:
- 実際に顧客を見る
- 髪に触れる
- 話を聞く
- 違和感を感じる
- 原因仮説を採用する
- 施術方針を決める
- 最終判断する

基本思想:

**池田にしかできない現場観察・違和感・最終判断へ時間を集中し、調査・比較・整理・変換・監査はAIへ渡す。**

## 6. noteの役割

noteは記事数を増やす場所ではない。

役割:
- 知的資産の公開
- 市場テスト
- 検索資産
- 信頼形成
- 商品への入口

新記事を書く前に確認する。

1. 既存記事へ追加できないか
2. 更新した方がいいか
3. 似た記事を統合できないか
4. 今の思想とズレていないか
5. 本当に新記事が必要か

記事は公開して完成ではない。現場結果や反証が増えれば更新して育てる。

## 7. 無料 / 有料の境界

### 無料記事

出してよいもの:
- 問題提起
- 現場で起きたこと
- 一次事例
- 考え方
- 判断の一部
- 検証途中の仮説
- 失敗・修正

無料記事を途中から隠して有料へ誘導するだけの撒き餌にはしない。

### 有料資産

「分かった」から「自分の現場でもできる」まで持っていく。

提供価値:
- 具体的な手順
- 記録方法
- 比較方法
- チェックリスト
- テンプレート
- 失敗条件
- 導入方法
- AIワークフロー

## 8. 商品価値の5層

商品候補は必ず次の5層に分ける。

1. Feature｜何を渡すか
2. Surface Problem｜読者が今使っている悩みの言葉
3. Desired Outcome｜解決すると何が変わるか
4. Avoided Loss｜何を失いたくないか
5. Core Value｜最終的に得る仕事・生活・判断の変化

商品説明はFeatureから始めず、Surface ProblemからCore Valueまで階段を作る。

## 9. 商品階段

```text
無料note
↓
小型有料note
↓
テンプレート / Starter Kit
↓
Playbook
↓
体系商品
↓
反復利用ツール
↓
継続課金
↓
Personal OS / プロダクト / ライセンス
```

最重要ルール:

**下の段階で需要が証明されなければ、上を作らない。**

## 10. Product Validation Gates v2

### Gate 0｜Problem

実在する問題か、読者自身の言葉で確認する。

証拠:
- 質問
- 相談
- 検索語
- コメント
- DM
- 類似ケース
- 現場観察

### Gate 0.5｜Desire / Value

Problemがあるだけでは商品化しない。

確認:
- 何を得たいのか
- 何を避けたいのか
- 今のやり方を続けるコストは何か
- 商品機能が欲しい未来へつながっているか
- 読者がまだ認識していない価値を説明できるか

Feature / Surface Problem / Desired Outcome / Avoided Loss / Core Value の5層が曖昧なら有料化しない。

### Gate 1｜Free Asset

無料noteで問題・一次事例・考え方を十分に渡す。

強い需要シグナル:
- どうやるのか
- 具体例が欲しい
- テンプレートが欲しい
- 自分にも使えるか
- どこから始めるか
- 実際の手順を知りたい

弱いシグナル:
- 面白い
- 参考になった
- すごい
- いいねのみ

### Gate 2｜Paid Asset

実際に金銭を払う価値があるか、小型有料note等で検証する。

最重要Evidenceは**購入**。

売れない時に本文を増やす前に、どこで止まったかを診断する。

1. 入口
2. 問題認識
3. 欲しい未来との接続
4. 商品価値の理解
5. 信頼
6. 価格と価値
7. 購入・利用摩擦
8. 今すぐ必要か

### Gate 2.5｜Use / Outcome

購入は完成証明ではない。

確認:
- 実際に使ったか
- どこで詰まったか
- 個別説明なしで使えたか
- 判断・行動が変わったか
- Outcomeへ近づいたか

### Gate 3｜Reusable Tool

購入後に繰り返し使われた部分だけテンプレート / Starter Kit化する。

### Gate 4｜Playbook

複数利用者・複数ケースで成立し、成立条件・不成立条件・例外が分かった方法だけ体系化する。

### Gate 5｜System / Product

勝った複数資産が反復行動として接続され、ソフトウェア化することで明確に価値が増える場合のみ検討する。

## 11. 現在地｜2026-08-25

現在は **Gate 0〜1：Problem / Desire / Free Asset Validation** が中心。

理由:
- 業界向けnoteには既存記事資産が30本ある
- 中核となる問題・思想は見えている
- 既存有料記事はあるが、第二エンジンとして十分な需要証明は弱い
- 何にお金を払うのか、どの価値認識から買うのかはまだ検証不足

今やること:
1. 既存30記事の資産分類を使う
2. 中核記事の問題設定を現在の思想へ統一
3. Theme A / B / CでSurface Problemと具体需要を観測
4. Desire / Valueの5層を埋める
5. 小型有料で購入を確認
6. 購入後の利用・Outcomeを見る

今はやらない:
- 新商品の大量企画
- Starter Kit先行開発
- Playbook先行開発
- オンライン講座
- コミュニティ
- SaaS
- 月額サービス
- 汎用美容師OS販売
- 個別コンサル主力化

## 12. 第二エンジンで避ける商品

- 個別添削必須
- Zoom必須
- DM無制限
- 顧客ごとのカスタマイズ必須
- 毎週ライブ必須
- 毎日SNS告知しないと売れない
- AIニュースを追い続けないと価値がなくなる

売れるほど池田の労働時間が増えるものは「第二の仕事」であり、第二収益エンジンではない。

## 13. 優先する資産

- 一度作れば何度も売れる
- 一対多
- 非同期
- 自己完結
- 半年後も価値がある
- 検索や紹介から売れる
- 現場を続けるほど内容が強くなる
- AIで運用負荷を下げられる

## 15. 需要検証3テーマ

### Theme A｜経験をどう残せば、次に使えるのか

主資産: IP-004 / IP-010 / IP-006

Core Value:
**働くほど、自分の専門性と知的資産が増えていく。**

観測する言葉:
- 記録テンプレ欲しい
- 何を残せばいい？
- カルテとの違いは？
- 何件くらい必要？
- 過去ケースをどう探す？

### Theme B｜AIをどう使えば、経験を再利用できるのか

主資産: IP-003 / IP-013 / IP-001

Core Value:
**AIによって仕事を増やすのではなく、人にしかできない判断へ時間を戻す。**

観測する言葉:
- 実際に何を入力してる？
- ChatGPTでどう管理してる？
- AIに任せない部分は？
- ケース検索どうしてる？
- ワークフローを見たい

### Theme C｜現場の判断を、どう発信・商品へ変えるのか

主資産: IP-002 / IP-029 / IP-004

Core Value:
**美容師として働くこと自体が、次の収益資産を生む。**

観測する言葉:
- 何を書けば専門性になる？
- ケースをどう記事にする？
- 無料と有料をどう分ける？
- 自分の経験のどこが売れる？
- noteを資産として残す方法は？

優先順位は A → B → C。

## 16. 記事を書く前の10問

1. 誰のどんな場面の問題か
2. 読者が実際に使う言葉は何か
3. 放置すると何を失うか
4. 解決すると何が変わるか
5. 商品が提供する機能は何か
6. なぜその機能で結果へ近づくのか
7. 池田が語る根拠は何か
8. 無料でどこまで渡すか
9. 有料で何を実行可能にするか
10. 購入後に何を観測すれば価値を検証できるか

この10項目が決まってから本文を書く。

## 17. 売れない時の禁止事項

- 理由を確認せず情報量を増やす
- 時間をかけた = 良い商品、と判断する
- PV / スキだけで需要証明する
- 無料を不完全にして有料へ誘導する
- 恐怖・損失を誇張して購入を煽る
- 未検証Outcomeを実績として売る
- AI生成物の量を商品価値とする
- 他者の販売実績を池田の再現可能性とみなす

## 18. 販売原則

**商品を売るとは、価値を誇張することではない。読者が見落としている問題・コスト・可能性を、理解できる順番で見えるようにすること。**

商品品質は書き手の自己評価ではなく、

**購入 → 利用 → 行動変化 → Outcome**

まで見て判断する。

詳細な販売・価値設計は `docs/IKEDA_OFFICE_SELLING_VALUE_FRAMEWORK_V1.md` を正本とする。
