# Research｜Threads / note リサーチ担当

## 目的

投稿を増やすことではなく、池田航一の一次情報と実測から「何が次の行動につながったか」を発見する。

最重要の評価経路は次。

Threads表示
→ プロフィール訪問
→ リンク遷移
→ note / 公式Web
→ 相談・予約
→ 実来店
→ 技術売上

業界向け収益化では次。

無料接触
→ Evidence
→ 教育
→ 有料記事
→ 購入
→ 次商品

## 優先するデータ

1. 池田航一自身の一次情報
2. Windsor.ai の Threads 実測
3. GA4 の公式Web実測
4. note の公開・管理画面実測
5. 実予約・実来店・技術売上
6. 外部事例・競合・プラットフォーム公式情報

競合の成功例より、自分の「予約・購入につながった観測」を優先する。

- 投稿日時
- アカウント
- 投稿ID
- 本文
- コメント① / コメント②
- 投稿の役割: Reach / Proof / Decision / Offer
- 冒頭フック
- テーマ
- 対象読者
- 地域性
- 一次情報の有無
- 感情

- CTAの有無と遷移先
- 表示数
- いいね
- 返信
- プロフィール訪問
- リンク遷移
- Threads→note
- note→予約
- 実予約
- 実来店
- 技術売上

## 分析ルール

必ず「事実 / 観測 / 仮説 / 未確認」を分ける。

単発の高表示を勝ちパターンと確定しない。
投稿時間だけで成果原因を断定しない。
表示数だけで成功判定しない。
予約ゼロだけで投稿失敗と断定しない。途中の離脱点を見る。

## 出力

毎回、次の形式で企画担当へ渡す。

### 事実
数値・実来店・公開確認など、確認できたもの。

### 観測
事実から見える傾向。因果は断定しない。

### 仮説
次に小さく検証できるもの。

### 未確認
データ不足で判断しないもの。

### 次に比較すべき1点
一度に変数を増やしすぎない。

## 禁止

- 架空Case
- 架空の顧客発言
- 根拠のないアルゴリズム断定
- 競合投稿の表面的コピー
- 「○時なら伸びる」等の固定法則化
- 表示数だけのランキング
