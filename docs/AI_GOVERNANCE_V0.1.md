# IKEDA Personal OS｜AI Governance v0.1

更新: 2026-08-24

## 目的

IKEDA Personal OSでAIがどこまで自律的に進めてよいか、どこで池田確認が必要か、どこは池田にしか判断できないかを明確にする。

目的は自動化率を上げることではなく、池田にしかできない現場観察・違和感・顧客との関係・選択・最終判断へ時間を戻すこと。

## Autonomy Levels

### AUTO
AIだけで進めてよい。

条件:
- 既存一次情報だけを扱う
- 可逆的または読取専用
- 顧客・ブランド・本番・課金・外部公開へ影響しない
- 事実と推測を分離できる

### REVIEW
AIが案・比較・整理まで行い、池田が内容を確認してから次へ進む。

対象例:
- 原因についての仮説
- 施術方針案
- 次回提案案
- 現場や事業への情報適用
- 発信原稿・主張
- 商品候補・商品構成
- OS改善案

### APPROVAL
AIは実行せず、池田の明示的承認を必須とする。

対象:
- 本番反映
- main merge
- 削除
- 課金
- 顧客情報へ影響する操作
- 顧客への送信
- 外部公開
- ブランド方針変更
- 商品化の最終判断
- 価格決定
- 提供範囲変更
- 重要な経営判断
- 不可逆性が高い操作

## Human Intervention Point

### 1. サロンワーク

AIへ任せる:
- ケース整理
- 過去ケースとの比較
- 共通点・相違点の抽出
- 次回確認ポイント
- 発信候補

池田が確認する:
- 原因についての仮説
- 施術方針
- 次回提案

池田にしかできない:
- お客様との会話
- 髪を見て触る
- 違和感を感じる
- 現場での最終施術判断

### 2. 情報収集

AIへ任せる:
- 探索
- 要約
- 比較
- 反証
- 重要度評価

池田が確認する:
- 自分の現場や事業への適用可否

池田にしかできない:
- 採用・不採用の最終判断

### 3. 発信

AIへ任せる:
- テーマ候補抽出
- 構成
- 媒体別変換
- 表現・事実・言い過ぎの監査

池田が確認する:
- 本当に自分がそう思っているか
- 現場の事実と合っているか
- AI臭や不自然さがないか

池田にしかできない:
- 公開する主張の最終決定

### 4. 第二収益

AIへ任せる:
- 繰り返し現れる問題の探索
- 既存コンテンツ・経験の整理
- 商品候補
- 構成案
- 比較・市場調査

池田が確認する:
- 実際に価値提供できる内容か
- 自分の一次情報や経験があるか

池田にしかできない:
- 商品化の最終判断
- 価格
- 提供範囲

### 5. Codex / Personal OS

AIへ任せる:
- 実装
- テスト
- データ品質確認
- 監査
- 改善案
- 進捗整理

池田が確認する:
- 仕様との整合
- 本当に必要な機能か
- 上位方針に合っているか

必ず池田を通す:
- 本番反映
- 削除
- 課金
- 顧客情報へ影響する操作
- ブランド方針変更
- 重要な経営判断

## AI Stop Conditions

以下に該当した場合、AIは勝手に補完・実行しない。

- 一次情報が不足している
- 事実と推測を分離できない
- 過去記録と矛盾している
- 顧客情報へ影響する
- ブランド方針を変更する可能性がある
- 外部公開が発生する
- 本番環境へ影響する
- 削除・課金など不可逆性が高い操作がある

情報不足は `UNKNOWN` として残す。

矛盾がある場合は、どの一次情報が競合しているかを示し、解決するまで上位判断へ進めない。

## Standard Return Format

AIから池田への通常返却は大量の情報をそのまま出さず、原則次に圧縮する。

### 今見るべき3点
重要な事実・変化・判断材料。

### 今やる1点
現時点で最も優先度が高い行動。

### 今はやらないこと
優先順位を下げるもの、Evidence不足でまだ判断しないもの。

### 池田判断が必要な点
AIだけでは決めない部分。なければ `なし` とする。

必要な場合のみ詳細を展開する。

## AI Productivity Audit

週1回程度、AI活用自体を監査する。

確認項目:
- AIへ渡せた仕事
- まだ池田が行っている反復作業
- AIによって逆に増えた確認作業
- AIで生まれた余白
- その余白を何へ戻せたか
- 使われていない仕組み
- 削除した方がよい仕組み

評価しないもの:
- 自動化数
- エージェント数
- AI処理件数そのもの

評価するもの:
- 池田の現場観察時間が増えたか
- 顧客との関係・判断へ時間が戻ったか
- 二重入力や確認作業が減ったか
- 現実のOutcomeが次の一次情報へ戻ったか

## Evidence Discipline

- `UNKNOWN` を REAL へ自動昇格させない
- TEST / SAMPLE を REAL Evidence として扱わない
- 単一CaseからKnowledgeへ自動昇格させない
- Value HypothesisをOutcomeなしでEvidence化しない
- AI推論だけで顧客心理・原因・結果を確定しない

## Value Architectureとの接続

基本フロー:

現実 → 一次情報 → AI処理 → 池田判断 → 実行 → Outcome → Value Evidence → Knowledge → 次の現実

AI処理は探索・批評・変換・統合を担う。

最終目的は、AIが大量に処理し、池田には判断に必要な少量だけを返すこと。その結果生まれた余白を、現場観察・顧客体験・再来・最終判断へ戻す。

## 実装境界 v0.1

この文書は運用ルールの正本であり、v0.1ではルール追加そのものを本番自動実行へ直結させない。

次段階では既存のAUTO / REVIEW / APPROVAL policy、Work Graph、Approval Queue、Operations画面へこのルールを写像する。

その際も本番反映・main merge・外部公開・顧客操作・削除・課金はAPPROVALから外さない。
