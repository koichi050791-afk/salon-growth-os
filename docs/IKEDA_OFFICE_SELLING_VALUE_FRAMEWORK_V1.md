# IKEDA OFFICE Selling & Value Framework v1

更新: 2026-08-25

## 1. 目的

第二収益エンジンでは、記事や商品の「情報量」を価値とみなさない。

売れない時に、理由を確認せず本文・具体例・情報量を増やすことを禁止する。

商品改善は、読者がどこで止まったかを分解してから行う。

```text
認知
↓
自分の問題だと気づく
↓
解決したいと思う
↓
商品の価値を理解する
↓
価格と価値を比較する
↓
購入する
↓
使う
↓
行動・判断が変わる
↓
結果が出る / 学びが返る
```

## 2. 商品の5層

すべての商品候補について、次の5層を分ける。

1. Feature｜機能
   - 何を渡すか
   - テンプレート、手順、チェックリスト、記事、ワークフロー等

2. Surface Problem｜表面的な悩み
   - 読者が現在使っている言葉
   - 「何を記録すればいいか分からない」等

3. Desired Outcome｜欲しい結果
   - その商品を使うと、仕事や生活の何が変わるか

4. Avoided Loss｜避けたい損失・未来
   - 何を失いたくないか
   - 時間、機会、経験、売上、信用、判断精度等

5. Core Value｜本質的価値
   - 読者が最終的に手にする状態
   - 商品機能ではなく、生活・仕事・意思決定の変化

商品説明はFeatureから始めない。
読者が今理解できるSurface Problemから入り、Core Valueまで階段を作る。

## 3. 抽象度ルール

本質の抽象度が高いほど、入口は日常語に戻す。

悪い入口例:
- 知的資産化しよう
- Personal OSを作ろう
- 仕組み化しよう
- AIで暗黙知を構造化しよう

入口候補:
- カルテを書いているのに、次回またゼロから考えている
- AIを使っているけど、SNS文章生成で止まっている
- 毎回SNSのネタを一から考えている
- 後輩に「感覚」としか説明できない
- 美容師歴は長いのに、自分の強みを言葉にできない

日常語で問題を認識させた後、本質へ連れていく。

## 4. Product Validation Gates v2

旧Gateを次へ更新する。

### Gate 0｜Problem

確認:
- 実在する問題か
- 読者自身の言葉で表現されているか
- 複数の独立した観測があるか

証拠:
- 質問
- 相談
- 検索語
- コメント
- DM
- 類似ケース
- 現場観察

### Gate 0.5｜Desire / Value

Problemが存在しても、解決のためにお金を払うとは限らない。

確認:
- 読者はその問題が解決したら何を得たいのか
- 何を避けたいのか
- 今のやり方を続けるコストは何か
- 商品機能と欲しい未来がつながっているか
- 読者がまだ認識していない価値を説明できるか

記録する5項目:
1. Feature
2. Surface Problem
3. Desired Outcome
4. Avoided Loss
5. Core Value

この5層が曖昧なら有料化しない。

### Gate 1｜Free Asset

無料記事で問題・一次事例・考え方を十分に渡す。

評価するのはPVやスキだけではない。

強いシグナル:
- どうやるのか
- 具体例が欲しい
- テンプレートが欲しい
- 自分にも使えるか
- どこから始めるか
- 実際の手順を知りたい
- 同じ問題に困っている

弱いシグナル:
- 面白い
- 参考になった
- すごい
- いいねのみ

### Gate 2｜Paid Asset

実際に金銭を払う価値があるかを小さく検証する。

最重要Evidence:
- 購入

同時に見る:
- どの言葉・問題から購入したか
- 何を期待して買ったか
- なぜ買わなかったか

売れない時に本文を増やす前に、次を確認する。

1. 入口で止まったか
2. 問題認識で止まったか
3. 欲しい未来につながらなかったか
4. 商品価値を理解できなかったか
5. 価値は理解したが価格に見合わなかったか
6. 信頼が足りなかったか
7. 今すぐ必要ではなかったか
8. 購入後の利用イメージが見えなかったか

### Gate 2.5｜Use / Outcome

購入は商品の完成証明ではない。

確認:
- 読者が実際に使ったか
- どこで詰まったか
- 説明なしで使えたか
- 判断や行動が変わったか
- 期待したOutcomeに近づいたか

商品としての品質は、文章量ではなく利用結果から判断する。

### Gate 3｜Reusable Tool

購入後に繰り返し使われた部分だけをテンプレート / Starter Kitへ切り出す。

### Gate 4｜Playbook

複数人・複数ケースで成立し、成立条件・不成立条件・例外が分かった方法だけ体系化する。

### Gate 5｜System / Product

勝った複数資産が反復行動として接続され、ソフトウェア化することで明確に価値が増える場合のみ検討する。

## 5. 売れない時の診断順

売れない = 中身不足、と判断しない。

```text
0. そもそも読まれているか
↓
1. 読者は自分の問題だと認識したか
↓
2. 解決したい強さはあるか
↓
3. 欲しい未来 / 避けたい損失につながったか
↓
4. 商品がその未来への手段だと理解されたか
↓
5. 信頼できたか
↓
6. 価格と価値が釣り合ったか
↓
7. 購入・利用の摩擦はなかったか
↓
8. 買った人は使えたか
↓
9. 行動・判断・結果が変わったか
```

修正は、止まっている段階だけに行う。

## 6. Theme A｜経験をどう残せば、次に使えるのか

### Feature
- 施術判断記録フォーマット
- ケース比較方法
- 次回確認項目
- AIで過去ケースを整理する方法

### Surface Problem
- カルテを書いているが次回に活かせない
- 前回なぜそうしたか思い出せない
- 何を記録すべきか分からない
- 経験が増えているのに再利用できない
- 後輩へ「感覚」でしか説明できない

### Desired Outcome
- 次回来店時に前回の判断を使える
- 似たケースを比較できる
- 自分の判断パターンが見える
- 説明や判断が速くなる
- 発信ネタや教育素材にも再利用できる

### Avoided Loss
- 同じ失敗を繰り返す
- 20年以上の経験が頭の中だけで消える
- 毎回ゼロから考える
- 年齢とともに体力だけが落ち、経験が収入へ残らない

### Core Value
**働くほど、自分の専門性と知的資産が増えていく。**

### 観測する言葉
- 記録テンプレ欲しい
- 何を残せばいい？
- カルテとの違いは？
- 何件くらい必要？
- 過去ケースをどう探す？

## 7. Theme B｜AIをどう使えば、経験を再利用できるのか

### Feature
- AIへの入力項目
- 過去ケース検索
- 比較・反例抽出
- 次回確認候補
- Human Gate
- AI Workflow

### Surface Problem
- ChatGPTを使っているが文章生成で終わる
- AIに何を入力すればいいか分からない
- 回答は出るが自分の現場に残らない
- チャットが増えるだけで仕事が軽くならない
- AIの答えをどこまで信用していいか分からない

### Desired Outcome
- AIが過去経験を探してくれる
- 比較・整理に使える
- 自分は最終判断へ集中できる
- 現場→記録→次回→発信までつながる
- AIを増やさず仕事時間を減らせる

### Avoided Loss
- AIツールを追い続ける
- プロンプトばかり増える
- 出力物は増えるが判断負荷も増える
- AIへ依存して専門家としての判断が薄くなる

### Core Value
**AIによって仕事を増やすのではなく、人にしかできない判断へ時間を戻す。**

### 観測する言葉
- 実際に何を入力してる？
- ChatGPTでどう管理してる？
- AIに任せない部分は？
- ケース検索どうしてる？
- ワークフローを見たい

## 8. Theme C｜現場の判断を、どう発信・商品へ変えるのか

### Feature
- Case→Content変換
- 記事テーマ抽出
- Before / After以外の見せ方
- 無料 / 有料振り分け
- 商品候補判定

### Surface Problem
- SNSのネタが毎回なくなる
- 自分の経験の何が価値なのか分からない
- 施術写真を出しても他美容師と差がつかない
- noteを書いても何を売ればいいか分からない
- 経験年数は長いが商品になるものが見つからない

### Desired Outcome
- 普段のサロンワークから発信ネタが生まれる
- 自分独自の専門性が見える
- 過去記事が検索・販売資産として残る
- 一度作ったものが繰り返し価値を生む
- 現場を続けながら第二収益を育てられる

### Avoided Loss
- 毎日投稿し続けないと売上が止まる
- 新作を作り続ける
- 過去の経験・記事が使い捨てになる
- 現場を減らさないと第二事業を作れない

### Core Value
**美容師として働くこと自体が、次の収益資産を生む。**

### 観測する言葉
- 何を書けば専門性になる？
- ケースをどう記事にする？
- 無料と有料をどう分ける？
- 自分の経験のどこが売れる？
- noteを資産として残す方法は？

## 9. Theme優先順位

現在は A → B → C の順で検証する。

理由:
- Aは池田の一次情報・ケース運用に最も近い
- BはAという独自一次情報をAIで増幅する構造なので模倣されにくい
- CはA/Bで蓄積した実例を市場価値へ変換する段階

Cから先に「noteの売り方」だけを商品化すると、一般的なnote販売ノウハウと競合し、池田固有の強みが薄くなる。

## 10. 記事・販売ページの設計順

文章を書く前に次を1枚で決める。

1. 誰のどんな場面の問題か
2. 読者が実際に使う言葉は何か
3. その問題を放置すると何を失うか
4. 解決すると何が変わるか
5. 商品が提供する機能は何か
6. なぜその機能で結果へ近づけるのか
7. 池田が語る根拠は何か
8. 無料でどこまで渡すか
9. 有料で何を「実行可能」にするか
10. 購入後に何を観測すれば商品価値を検証できるか

この10項目が決まってから本文を書く。

## 11. 販売学習の扱い

外部の販売教材・コピーライティング・マーケティング理論は、盲目的に採用しない。

AIへ任せる:
- 販売理論の探索
- 比較
- 共通原則抽出
- 反証
- 池田の商品候補への適用案

池田が判断する:
- 読者像
- 自分の一次経験との整合性
- 誇張にならないか
- 本当に提供可能な価値か
- 採用 / 不採用

販売テクニックによって、商品価値以上に期待を膨らませない。

## 12. 禁止事項

- 売れない理由を確認せず情報量を増やす
- 「時間をかけた = 良い商品」と判断する
- PV / スキだけで需要証明する
- 無料記事を不完全にして有料へ誘導する
- 恐怖・損失を誇張して購入を煽る
- 未検証Outcomeを実績として売る
- AI生成物の量を商品価値とする
- 他者の販売実績をそのまま池田の再現可能性とみなす

## 13. IKEDA OFFICEの販売原則

**商品を売るとは、価値を誇張することではない。読者が見落としている問題・コスト・可能性を、理解できる順番で見えるようにすること。**

そして商品品質は、書き手の自己評価ではなく、

**購入 → 利用 → 行動変化 → Outcome**

まで見て判断する。
