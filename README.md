# 池田航一｜美容師OS

池田航一のサロンワークと経営実務から、現在収益と将来資産を同時に残しながら、池田本人が関与しなくてよい反復作業を減らすための事業OS。

## 最上位目標

家族との時間を守りながら、池田航一の時間・判断・経験が、本人の労働時間以上の価値と収入を生み続ける事業を作る。

月間技術売上130万円は最上位目標ではなく、9:00〜18:00前後・1人営業・長時間労働に依存しない収益条件を発見するための検証指標として扱う。

## 現在フェーズ｜2026-09-04

Phase1｜Human Dependency Removal

現在の実装基準は GitHub Issue #61。

最優先は次の3領域だけ。

1. KPI日報
2. 判断価値がある施術Case
3. 予約・残キャパは、勤務先システムへ接続しない匿名の最小観測のみ

新しいDB、ダッシュボード、Agent群、SaaSを増やす前に、既存運用から池田の転記・集計・検索・確認作業を減らす。

## 勤務先データの境界

現在のBeautyMeritは勤務先の予約基盤であり、池田個人の2028事業OSには接続しない。

顧客氏名、電話番号、メール、識別可能な予約履歴、他スタッフの予約、会社全体の顧客・売上データを取得しない。

予約の自動連携は、独立後に池田自身が管理する予約システムが決まってから設計する。

## 営業日報の最小入力

勤務中は、池田が通常業務で把握した自分の営業数字だけをChatへ1回伝える。

基本は次の5要素。

1. 日付
2. 技術売上
3. 客数
4. 次回予約数
5. メニュー

書式、順番、`【】` は不要。1メッセージの自然文でよい。

新規人数、残キャパ、空き時間、空き理由、気づきは、その日に自然に把握できていて意味がある場合だけ追加する。不明値を埋めるために勤務先システムを巡回しない。

客単価、次回予約率、月間累計、営業日平均、目標差、欠損・重複・構造矛盾の確認はシステム側で行う。

正常時は再確認を要求しない。

## Caseの最小入力

判断価値があるCaseだけ残す。

池田は30〜60秒程度の自然文で一次情報を伝えればよい。フォームを埋めることを仕事にしない。

AI側で次へ整理する。

1. 相談
2. 確認した事実
3. 今回の判断
4. あえてしなかったこと
5. 結果（明示されている場合のみ）
6. 次回確認

全項目が入力されていなくてもよい。不明は不明のままにする。

入力後は、構造化、事実と仮説の分離、類似Case検索、Decision候補、Knowledge候補、必要なら発信候補までAI側の仕事とする。

入力にない情報は補完しない。事実と仮説を混同しない。単一CaseからKnowledgeを確定しない。

## 現在の原則

正常は無音。

池田にしかできない仕事は残す。

- 顧客との対話
- 髪と状態の観察
- 施術設計
- 技術
- 顧客心理の解釈
- 重要な経営判断
- Knowledge正式採用
- AI権限変更

池田でなくてよい仕事はシステム側へ移す。

- 数える
- 転記する
- 欠損や重複を探す
- 検索する
- 比較する
- Caseを文章へ整える
- 類似Caseを探す
- Decision / Knowledge候補を整理する

## 二重作業禁止

AIがSheets反映、計算、Case整形、類似検索を完了した後に、池田が同じ内容を別画面、別フォーム、別台帳へ再入力・再集計しない。
